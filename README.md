# Прибрано — шаблон сайту клінінгової служби

MVP для служби прибирання з виїздом (квартири, будинки, малі офіси). Клієнт обирає тип прибирання й параметри, одразу бачить орієнтовну вартість і надсилає заявку з фото. Власник у кабінеті бачить склад заявки, телефонує клієнту, погоджує ціну й час, а клієнт бачить оновлення за приватним посиланням.

Шаблон розрахований на одну компанію: окремий екземпляр і окрема база. Назва, контакти, місто, ціни, гра й персонажі налаштовуються в кабінеті без коду.

## Стек

Nuxt 4.6 (SSR, серверні маршрути) · Vue 3.5 `<script setup lang="ts">` + Pug + SCSS-токени · Pinia · Three.js 0.187 + TresJS 5.11 + Cientos 5.11 · PostgreSQL (postgres.js), локально PGlite · sharp · zod · pnpm.

Версії зафіксовано після перевірки сумісності: Cientos 5.11 вимагає `@tresjs/core ^5.9.1` і `vue >=3.5.17`, Core 5.11 — `three >=0.133`. Модуль `@tresjs/nuxt` не використовується, бо тягне за собою `@nuxt/ui`. TresJS підключено напряму з `templateCompilerOptions`.

## Швидкий старт

```bash
pnpm install
cp .env.example .env   # впишіть свій NUXT_ADMIN_PASSWORD (мінімум 10 символів)
pnpm dev               # http://localhost:3000 (або --port 3010)
```

Без `DATABASE_URL` дані зберігаються у вбудованій PostgreSQL-сумісній PGlite (`.data/pglite`). Для production див. [docs/DEPLOY.md](docs/DEPLOY.md).

| Команда | Що робить |
|---|---|
| `pnpm dev` | розробка |
| `pnpm build` / `pnpm preview` | збірка й запуск `.output` |
| `pnpm typecheck` | vue-tsc, разом із Pug-шаблонами |
| `pnpm test` | юніт-тести формули |
| `pnpm smoke [url]` | наскрізна перевірка API на запущеному екземплярі (вигадані дані, після себе прибирає) |

### Клієнтський шлях

1. **Калькулятор** (`/calculator`): тип (у картці — що входить і що ні), площа (степпер 10–500 м² із ручним вводом), кімнати, санвузли. Для вікон — стулки й балкон, для «Інше» — опис. Далі додаткові послуги з лічильниками, регулярність зі знижкою, сильне забруднення й живий розрахунок.
2. **Кошик** (`/cart`): кілька послуг. Однакові позиції об'єднуються, різні налаштування лишаються окремими рядками. Є кількість, редагування, видалення зі «Скасувати», порожній стан. Відома сума й позиції «за фото» показуються окремо.
3. **Оформлення** (`/checkout`): ім'я, телефон +380, адреса, «за місто», дата й час (час — тільки після дати), до 3 фото (прев'ю, повтор, видалення; для «Інше» хоча б одне обов'язкове), коментар, згода. Коди домофона й ключі форма не збирає. Помилки показуються біля полів. Чернетка й кошик переживають перезавантаження.
4. **Відправка**: успіх показується лише після запису в базу. Повтор після збою з тим самим ключем повертає ту саму заявку.
5. **Сторінка заявки** (`/order/<токен>`): склад, статус, попередній розрахунок, підсумкова ціна й час, кнопка копіювання посилання. Сторінка сама оновлюється, коли власник щось змінює. Після заявки можна зіграти в необов'язкову гру.

### Кабінет `/admin`

Розділи «Заявки» (пошук, фільтри статусу й періоду, оновлення), «Тарифи», «Компанія», «Гра», «Персонажі», «Доступ». Картка заявки: контакт, приватні фото, склад, побажання, попередній розрахунок, історія, підсумкова ціна, погоджений час, статус, приватна нотатка. Статус «погоджена» не ставиться без ціни й часу. Видалення заявки разом із фото — через діалог підтвердження.

### Безпека й дані

- Сервер заново рахує заявку за поточним прайсом і зберігає знімок прайсу та розрахунку.
- Origin перевіряється на всіх мутаційних запитах. Обмеження запитів зберігається в БД, тож працює й на serverless.
- Пароль хешується через scrypt. Сесія — httpOnly SameSite=Strict cookie, у базі лежить лише хеш токена. Після зміни пароля всі сеанси закриваються.
- Фото: формат визначається з вмісту, зображення зменшується, EXIF і GPS видаляються. Публічних адрес у фото немає.
- Публічне API не віддає телефон, адресу, фото й нотатку.
- Політика зберігання й видалення даних описана в [docs/DATA-POLICY.md](docs/DATA-POLICY.md).

Формула — [docs/PRICING.md](docs/PRICING.md). Адаптація й витрати — [docs/ADAPTATION.md](docs/ADAPTATION.md). Обмеження — [docs/LIMITATIONS.md](docs/LIMITATIONS.md). Ліцензії — [LICENSES.md](LICENSES.md).

## 3D

П'ять персонажів, кожен прив'язаний до типу прибирання:

| Персонаж | Тип | Пізнаваний за |
|---|---|---|
| Гудзя | Підтримуюче | корпус, бампер, шланг, металева труба, щітка |
| Мопик | Генеральне | відро з водою, ручка, швабра й мотузки |
| Пшик | Після ремонту | пляшка, етикетка, тригерна голова, сопло, курок |
| Скрипик | Миття вікон | ручка з гумовими кільцями, Т-подібне лезо |
| Пухлик | Інше | двошарова губка з порами, мильні бульбашки |

Що є в сцені:

- Справжня геометрія: обертання мишею й пальцем, обмежена камера, кнопка скидання ракурсу, тінь, процедурне освітлення.
- Анімації: вітання рукою, рідкісне кліпання, дихання. Перемикання — пружинне, тому швидкі повторні кліки не ламають анімацію. Усі моделі готуються заздалегідь.
- Репліка прив'язана до проєкції точки над головою, а на вузькому екрані закріплена вгорі. Коли персонаж відвернутий або сцену тягнуть, репліка ховається.
- DPR обмежено до 1,75. Рендер ставиться на паузу поза екраном і у фоновій вкладці. При reduced motion анімації вимикаються, а рендер іде лише на вимогу.
- Є стан завантаження, помилка з кнопкою повтору і SVG-постер без WebGL. Замовлення працює в усіх цих станах.

Мінігра «відмий дзеркало»: плями лежать на CanvasTexture за UV скла. Пензель стирає їх через raycast, і лише коли першим влучанням є саме скло, тому рама й задня панель плями перекривають. Режими «Чистити» й «Обертати» розділені, прогрес показується. У кабінеті є три режими гри; бонус дається один на заявку й погашається вручну.

**Не перевірено:**

- **Реальний телефон** — перевірялася лише емуляція 375 px.
- **Service worker і офлайн-екран** — вбудований браузер відхиляє реєстрацію SW. `sw.js`, `manifest.webmanifest`, іконки й `offline.html` віддаються коректно, але кешування й офлайн-режим треба перевірити в Chrome чи на телефоні.
- **Production PostgreSQL і хостинг** — перевірено лише на PGlite (той самий SQL-діалект). Сайт ніде не розгорнуто.
- **Вигляд фреймів у Figma** — після імпорту не відкривався: на тарифі Starter дуже обмежена кількість MCP-викликів.
