# Персональні дані: що зберігаємо, скільки й як видалити

Текст для відвідувачів — сторінка `/privacy` ([`app/pages/privacy.vue`](../app/pages/privacy.vue)). Цей файл описує технічну реалізацію для власника й розробника.

## Що зберігається

| Дані | Де | Хто бачить |
|---|---|---|
| Імʼя, телефон, адреса, «за місто», коментар | таблиця `orders` | лише власник у кабінеті |
| Бажані дата й час, склад, розрахунок, знімок прайсу | `orders` | власник; клієнт — за приватним посиланням (без телефону й адреси) |
| Приватна нотатка власника | `orders.owner_note` | лише власник |
| Фото (до 3) | `uploads.bytes` (bytea у PostgreSQL) | лише власник через `/api/admin/photos/:id` із сесією |
| Історія змін | `order_events` | лише власник |
| Хеш IP для обмеження запитів | `rate_hits` (HMAC, не сама IP) | ніхто; чиститься через добу |

Не збираються: коди домофона, ключі, паролі, платіжні дані.

## Фото

- Реальний формат визначається з вмісту файлу (sharp), а не з розширення: JPEG, PNG, WebP, до 12 МБ.
- Зменшуються до 1600 px, перекодовуються у WebP; EXIF, GPS, XMP та ICC відкидаються.
- Не мають публічної адреси. Поки фото не привʼязане до заявки, його не віддає жоден маршрут. Після привʼязки фото доступне лише власнику з активною сесією, з `Cache-Control: private, no-store`.
- Фото без заявки видаляються через 24 години (лениво, під час відкриття кабінету).

## Строк зберігання

Кабінет → «Компанія» → «Знеособлювати… через N днів» (за замовчуванням 365). Для заявок у статусі «Виконана» або «Скасована», які не змінювалися N днів, імʼя замінюється на «Видалено». Телефон, адреса, коментар і нотатка очищаються, фото видаляються. Склад і суми лишаються для обліку. Процедура запускається лениво при відкритті списку заявок (`applyRetention`), окремий cron не потрібен.

## Видалення за запитом клієнта

1. Знайдіть заявку в кабінеті: пошук за телефоном чи імʼям або за посиланням клієнта.
2. Картка заявки → «Видалення» → «Видалити заявку» → підтвердіть.
3. Заявка видаляється разом із фото, історією й бонус-кодом (каскадне видалення), без відновлення.
4. Резервні копії бази (якщо їх робить хостинг PostgreSQL) зберігаються за політикою провайдера. Укажіть цей строк у політиці конфіденційності клієнта.

## Секрети

`DATABASE_URL`, `NUXT_ADMIN_PASSWORD`, `NUXT_SECRET` задаються лише змінними середовища на сервері. У клієнтський бандл потрапляє тільки `NUXT_PUBLIC_SITE_URL`.
